# Story 7.3 — Auto-CIALA: Consulta Automática a Cada Nova Escala

## Status: Done

## Story

**Como** sistema,  
**Quero** consultar o CIALA automaticamente para todo navio com IMO que tenha nova escala ativa,  
**Para que** o risco e a prioridade PSC estejam sempre atualizados no dashboard sem intervenção manual.

## Contexto

Atualmente a consulta ao CIALA é manual (botão na UI). O risco de um navio pode mudar entre visitas — um navio que era P3 na última escala pode ser P1 na próxima. Por isso, **a cada nova escala criada, mesmo para navio já conhecido, o CIALA deve ser consultado**.

A consulta roda dentro do scheduler, **após** o ciclo ZP-21 (7.1) **e** após o auto-IMO (7.2) — garantindo que o navio terá IMO antes de tentar o CIALA.

**Query existente:** `ListVesselsForCIALA` retorna navios com IMO mas sem `risk_level`. Para 7.3, precisamos de uma query adicional que pegue navios com IMO e port call ativo mas cujo CIALA não foi consultado nesta visita.

**Critério de "nova escala":** o scheduler mantém rastreio por `last_ciala_checked_at` na tabela `vessels` — se a escala ativa foi criada após o último check do CIALA, reprocessa.

## Acceptance Criteria

- [ ] AC1: Após auto-IMO, o scheduler consulta CIALA para navios com IMO e escala ativa não consultada desde a criação da escala
- [ ] AC2: Consulta inclui navios já com `risk_level` (atualiza a cada nova escala)
- [ ] AC3: Resultado persiste via `UpdateVesselCIALA` (mesmos campos do fluxo manual)
- [ ] AC4: Falha na consulta → loga e continua para o próximo navio (não interrompe ciclo)
- [ ] AC5: Sessão CIALA compartilhada no scheduler (login único, reutilizado entre ciclos, reset em caso de expiração)
- [ ] AC6: `vessels.last_ciala_checked_at` é atualizado após cada consulta bem-sucedida
