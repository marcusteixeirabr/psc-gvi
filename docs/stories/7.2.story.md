# Story 7.2 — Auto-IMO: Busca Automática de IMO para Novos Navios

## Status: Done

## Story

**Como** sistema,  
**Quero** buscar o IMO automaticamente no VesselFinder para cada novo navio criado pelo ZP-21,  
**Para que** o operador não precise fazer isso manualmente a cada navio novo detectado.

## Contexto

Quando o scraper ZP-21 detecta um navio novo (não está no BD), cria o registro com `imo = NULL`. Atualmente o operador precisa clicar "Buscar IMO" na página do navio. Com ~60 navios/mês e recorrência alta, a maioria já tem IMO — mas os novos bloqueiam a pipeline automática (sem IMO → sem CIALA → sem prioridade).

A auto-busca de IMO roda **dentro do scheduler**, logo após o ciclo ZP-21 da Story 7.1.

**Restrição anti-bot VesselFinder:** delay de 500ms entre requisições (já aplicado no `BatchStream` manual). A frequência é baixa (~3-5 navios novos/mês).

**Query existente:** `ListVesselsWithoutIMO` já retorna navios acompanhados sem IMO com port call ativo.

## Acceptance Criteria

- [ ] AC1: Após cada ciclo ZP-21, o scheduler verifica navios com `imo IS NULL` e port call ativo
- [ ] AC2: Para cada navio sem IMO, chama `scraper.FindIMO` com delay de 500ms entre chamadas
- [ ] AC3: IMO encontrado → persiste via `UpdateVesselIMO` e loga o resultado
- [ ] AC4: IMO não encontrado → loga o erro e continua (não interrompe os demais)
- [ ] AC5: Navio com múltiplos candidatos (ambiguidade) → loga e pula (sem persistir dado incerto)
- [ ] AC6: Máximo de 10 buscas por ciclo (evita burst em caso de importação massiva)
