# Story 7.1 — Scheduler Interno: Ciclo Horário Automático ZP-21

## Status: Done

## Story

**Como** administrador do sistema,  
**Quero** que o scraping do ZP-21 execute automaticamente a cada hora,  
**Para que** o dashboard esteja sempre atualizado sem depender de ação manual.

## Contexto

Atualmente o scraping do ZP-21 é disparado manualmente via POST `/scrape/zp21` (botão na UI). O sistema precisa executar esse ciclo automaticamente para ser útil em produção.

**Decisão de arquitetura confirmada:** goroutine interna com `robfig/cron/v3`.
- Binário único, sem dependência externa (sem cron do SO, sem Redis, sem workers separados)
- Acesso direto ao pool de conexões PostgreSQL
- Status visível futuramente no painel de saúde (Epic 8)

O scheduler inicia junto com o servidor HTTP e encerra graciosamente via signal (SIGINT/SIGTERM).

## Acceptance Criteria

- [ ] AC1: Scraping ZP-21 executa automaticamente a cada hora sem intervenção manual
- [ ] AC2: Primeiro ciclo ocorre 1 minuto após o start do servidor (não espera 1 hora inteira)
- [ ] AC3: Cada ciclo loga: início, duração, resultado (`ScrapeResult.Summary()`) e erros
- [ ] AC4: Servidor encerra graciosamente ao receber SIGINT/SIGTERM (drain do scheduler antes de fechar)
- [ ] AC5: O endpoint manual POST `/scrape/zp21` continua funcionando (disparo sob demanda)
- [ ] AC6: Erros no ciclo automático são logados mas NÃO derrubam o servidor

## Tasks

## Notes

- O scheduler recebe o mesmo `*sqlc.Queries` e `zp21URL` que o handler manual usa hoje
- `ZP21_URL` já existe em `internal/config/config.go`
- Ciclo do job: `FetchManobras` → `ProcessManobras` → log do resultado
- O cron expression `@every 1h` do robfig/cron é suficiente
- Para o primeiro disparo com 1 minuto de delay: usar `@every 1h` com `cron.New()` e agendar também um `time.AfterFunc(1*time.Minute, jobFn)` na inicialização, OU usar expressão cron com offset de 1 minuto a partir do horário atual
