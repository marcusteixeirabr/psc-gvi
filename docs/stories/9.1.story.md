# Story 9.1 — Paginação: Navios e Escalas (50 linhas/página)

## Status: Done

## Story

**Como** inspetor,  
**Quero** que as listas de Navios e Escalas exibam no máximo 50 registros por página,  
**Para que** a interface permaneça rápida e navegável à medida que o histórico cresce.

## Contexto

Atualmente as listas carregam todos os registros de uma vez. Com ~60 navios/mês e escalas acumulando ao longo do tempo (720+ ao final do primeiro ano), a ausência de paginação vai degradar a experiência. A paginação é server-side via query param `?page=N`.

**Páginas afetadas:** `/vessels` (lista de navios) e `/escalas` (lista de escalas).

**Tamanho de página:** 50 registros — adequado para exibição em monitor sem scroll excessivo.

## Acceptance Criteria

- [ ] AC1: `/vessels` exibe no máximo 50 navios por página; navega via `?page=N`
- [ ] AC2: `/escalas` exibe no máximo 50 escalas por página; navega via `?page=N`
- [ ] AC3: Controles de paginação mostram: "Página X de Y · Total Z registros"
- [ ] AC4: Botões Anterior / Próximo desabilitados quando não há página anterior/posterior
- [ ] AC5: Filtros e parâmetros existentes (status, mês, navio) são preservados na navegação entre páginas
- [ ] AC6: `?page=1` é o padrão; valores inválidos (ex: `?page=0`, `?page=999`) são normalizados silenciosamente

## Notes

- Helper de paginação reutilizável: `pagination.FromQuery(c *gin.Context, totalItems, pageSize int) Page`
  - Lê `c.Query("page")`, garante mínimo 1, calcula `TotalPages = ceil(total/size)`, clipa em range válido
- Controles no template: `← Anterior` | `Página X de Y (Z registros)` | `Próximo →`
- Links de paginação preservam todos os outros query params via `?page=N&status=active&mes=...`
- Para navios: `CountVessels` conta acompanhados (ou todos, se `?all=1` para admin)
- Para escalas: `CountEscalas` replica os filtros de `ListEscalas` com `COUNT(*)`
- `ListEscalasPaged` replica `ListEscalas` com `LIMIT 50 OFFSET $5` (offset como 5º parâmetro)
