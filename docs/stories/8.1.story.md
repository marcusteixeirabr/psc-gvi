# Story 8.1 — Métricas do Scheduler: Tabela `scraper_runs`

## Status: Done

## Story

**Como** administrador do sistema,  
**Quero** que cada execução automática do scheduler seja registrada no banco de dados,  
**Para que** eu possa ver o histórico de execuções, erros e performance de cada scraper.

## Contexto

O scheduler (Epic 7) roda automaticamente mas não deixa rastro persistente além dos logs do console. Em produção, logs se perdem entre deploys. A tabela `scraper_runs` é a base para o painel de saúde (8.2) e os alertas por e-mail (8.3).

**Scrapers registrados:**

| Scraper | Descrição |
|---------|-----------|
| `zp21` | Ciclo principal de scraping ZP-21 |
| `auto_imo` | Busca automática de IMO via VesselFinder |
| `auto_ciala` | Consulta automática ao CIALA |

Cada execução gera **um registro por scraper** com status, duração e métricas relevantes.

## Acceptance Criteria

- [ ] AC1: Tabela `scraper_runs` criada via migration com campos: id, scraper, started_at, finished_at, duration_ms, status, rows_found, items_processed, items_failed, error_message
- [ ] AC2: Ao final de cada ciclo ZP-21, um registro `scraper=zp21` é inserido com resultado do `ScrapeResult`
- [ ] AC3: Ao final do `RunAutoIMO`, um registro `scraper=auto_imo` é inserido com contagem de found/failed
- [ ] AC4: Ao final do `RunAutoCIALA`, um registro `scraper=auto_ciala` é inserido com contagem de found/failed
- [ ] AC5: `status` = `'success'` se sem erros, `'partial'` se houve erros parciais, `'error'` se falha total
- [ ] AC6: `error_message` preenchido apenas quando `status = 'error'` (falha total do scraper)

## Notes

- Schema da tabela:
  ```sql
  id BIGSERIAL PRIMARY KEY,
  scraper VARCHAR(50) NOT NULL,        -- 'zp21' | 'auto_imo' | 'auto_ciala'
  started_at TIMESTAMPTZ NOT NULL,
  finished_at TIMESTAMPTZ NOT NULL,
  duration_ms INTEGER NOT NULL,
  status VARCHAR(20) NOT NULL,         -- 'success' | 'partial' | 'error'
  rows_found INTEGER DEFAULT 0,        -- para zp21: ManobrasRow count
  items_processed INTEGER DEFAULT 0,   -- vessels/port calls atualizados
  items_failed INTEGER DEFAULT 0,      -- erros parciais
  error_message TEXT                   -- só em falha total
  ```
- `ScrapeResult` já tem `RowsFound`, `PortCallsUpdated`, `Errors` — mapear diretamente
- `RunAutoIMO` e `RunAutoCIALA` devem passar a retornar uma struct `RunResult{Found, Failed int, Err error}` para que `RecordRun` possa persistir
